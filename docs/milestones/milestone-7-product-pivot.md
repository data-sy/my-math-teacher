## 왜 피벗인가 (문제 정의)

MMT 3기둥 = ① 지식그래프 시각화 · ② 진단 · ③ 맞춤학습지. **문제 풀 부재가 ②③ 공통 병목**이고 ①만 무관하다.

- 기존 ②진단 = 학생이 문제를 풀고 정오답을 채점 → DKT(TF Serving)가 취약점 추론. **서빙할 실제 문항이 없다**(기존 `items` 8,120건은 가라 이미지 + 저작권 제약으로 공개 서비스에 못 올림).
- 기존 ③맞춤 = 취약점에 맞춘 학습지 출제 → (원 의도: 다시 풀려 재진단하는 루프). **이것도 같은 문제 풀에 의존** → 원천적으로 막힘.

두 갈래(1. AI 로 문제 생성 / 2. 우회) 중 **품질 보장 불가로 1을 버리고 2를 택함.** 우회의 구체가 아래 결정들이다.

> 이 피벗은 로드맵 `[GTM] 컨설팅 어젠다`(2026-07-06) ①②③ 을 사용자 판단으로 선결정한 것이다.
> 컨설팅은 이후 검증·GTM 관점으로 수행하되, 제품 방향은 본 문서가 정본.

## 새 제품 루프 (종이 플로우)

```
홈(그래프 기반 자가진단 가치제안)
  → 영역 진입 (학교급/단원 선택으로 그래프 진입점 좁히기)
  → 그래프 적응형 문답  ← 화면 1개당 개념 1개, "알아요 / 몰라요"
      · 개념 이름 + 대표 예시(미니 그림/한 줄)
      · "알아요" → 그 아래 선수지식 가지 skip
      · "몰라요" → 그 개념의 선수지식으로 drill-down
  → 취약점 결과
      · AI(DKT) 시급도순 우선순위  ← self-report OX 를 정오답(안다=맞음/모른다=틀림)으로 매핑해 DKT 입력
      · 그래프 학습 경로(무너진 토대 → 목표 개념 순서) + 개념별 외부 학습 링크(EBS 등)  ← 학습지 출제 대체
```

MBTI식 "클릭하면 답에 따라 다음 화면이 갈리는" 흐름 = 지식그래프를 **테스트 엔진 자체**로 쓰는 것.

## 결정 (2026-07-11 사인오프)

- **D1 — 진단 = self-report OX.** 문제 풀 부재 우회. "정오답"을 "안다/모른다"로 대체. *근거:* 서빙 가능한 실문항이 없음.
- **D2 — 진단 엔진 = 그래프 적응형 문답(B안).** 개념 나열형(A안)이 아니라 답에 따라 경로가 갈리는 그래프 순회. 개념 1,631개를 다 못 묻는 문제를 "알아요→하위 skip"으로 해소해 화면 수를 짧게 유지. *A/B 프로토타입 비교는 착수 시 열어두되 B 에 무게.*
- **D3 — 시급도 = 그래프 점수(DKT 퍼센트 폐기).** ⚠️ **2026-07-13 개정으로 폐기·역전.** 원래 근거는 "DKT 에 self-report 를 먹이면 의미론상 garbage-in → 가짜 정밀도"였으나, **가장 시급한 것부터 하나씩 배포** 전략상 진단 엔진 신규 구축을 보류하고 **DKT(TF Serving)를 유지**하기로 결정. → **D3-R 참조.**
- **D3-R (2026-07-13) — 시급도 = DKT 유지, self-report 를 정오답으로 매핑.** self-report OX 를 **안다=맞음(정답) / 모른다=틀림(오답)** 으로 배선해 기존 DKT 입력 시퀀스(`AnswerService.findAIInput`)에 흘려넣고 `probabilityList` 로 시급도 산출. *트레이드오프:* 자기보고를 정오답 신호로 쓰는 의미론적 부정확(과대평가 학생이 모델 오염, R1)을 감수하는 대신 "AI 진단" 자산·포지셔닝을 보존하고 진단 엔진 재작성을 회피. **"인증"이 아니라 "자가진단 가이드"로 정직하게 프레이밍**해 방어(R1).
- **D4 — 맞춤 = 그래프 학습 경로 + 외부 링크 큐레이션.** ⚠️ **2026-07-13 개정으로 확장**(원래 "외부 링크만"). 학습지 출제 제거. ①그래프 위에 "무너진 토대 → 목표 개념" 학습 순서를 경로로 제시(다운로드 아닌 인터랙티브 가이드, 그래프 해자 활용) + ②개념별 EBS 등 외부 무료 자료 링크. 상위 취약 개념부터, 전 개념 채울 필요 없음.
- **D5 — 문답 카드 = 개념 이름 + 대표 예시.** 이름만이면 "내용은 아는데 이름을 몰라" 오답 유발(자기보고 고질병) → 인식용 미니 예시 동반.
- **D6 — 기술 스택 = React 새로 짜기(`web/`).** ✅ **2026-07-13 확정**(마이그레이션 아님 — 프레임워크 통째 교체라 점진 이주가 오히려 지저분). 커리어 수요(React) + 어차피 크리티컬 패스를 새로 그리는 지금이 전환 최저비용 시점. 백엔드·배포·그래프 데이터 무변경. **초기 범위 = 최소 런치 MVP**(홈·자가진단 문답·결과·맞춤·로그인/에러·개념그래프 탐색); 채점 상세·이력·회원수정 등 부가화면은 오픈 후 이식. *주의: 진단 유지로 문답·결과 화면이 살아남아 순수 피벗보다 재작성 표면이 다소 큼(R2).* → **기존 [Design] "React 이주는 launch 후" 결론을 supersede**(아래).
- **D7 — 모바일 퍼스트.** 기존 반응형이 깨지는 옛 Vue 템플릿을 폐기, 모바일 UX 기준으로 재설계.
- **레포 = 모노레포 유지(새 레포 X).** 라이브 백엔드·배포·그래프 데이터·M2/M4/M6 포폴 서사를 버리지 않음. "새로 시작하는 해방감"은 프론트 fresh 리빌드로 얻고, 방향 전환은 M7 히스토리로 남김.

### 기존 [Design] 트랙과의 관계 (supersede 명시)

로드맵 `[Design] 실배포 전 리디자인`(2026-06-23)의 결론은 **"launch 까지 Vue 유지 + React 이주는 launch 후 재검토"** 였다. M7 이 이를 갱신한다: **self-report 피벗으로 프론트를 어차피 새로 그리게 되어, React 전환을 이 리디자인과 합쳐 지금 수행**한다. 그 트랙의 P0/P1 산출물(히어로·결과 재설계·셸·토큰·폼 등, 전부 Vue)은 **UX 결정은 재사용**하되 **코드는 React 재작성으로 대체**된다.

## 리스크 레지스터

- **R1 자기보고 정확도(개정으로 상향)** — 학생 과대평가 위험. **D3-R 로 self-report 가 DKT 입력이 되므로 오염이 곧 모델 출력 왜곡으로 직결**(정오답 학습 모델에 자기보고를 먹이는 의미론적 부정확). 완화: D5(이름+예시), "인증"이 아니라 "자가진단 학습 가이드"로 정직하게 프레이밍, 시급도를 절대 점수 아닌 상대 우선순위로 제시. 실문항 확보 시 실채점으로 승격.
- **R2 React 새로 짜기 스코프** — auth/OAuth 인터셉터·router·`api.js`·레이아웃·PrimeVue 가 전부 Vue → 재작성 대상. 완화: 최소 런치 MVP 로 범위 한정(부가화면 오픈 후), 백엔드/인프라 무변경으로 리스크 격리. *단 진단 유지로 문답·결과 화면이 살아남아 순수 피벗 대비 표면이 다소 큼(학습지 출제 화면 제거분만 순감).*
- **R3 포지셔닝** — "AI 진단" 간판 **유지**(D3-R). self-report 를 정오답으로 매핑해 DKT 가 시급도를 내므로 "AI 진단" 서사 성립. 이력서/포폴 문구는 큰 조정 불필요하나, self-report 기반임을 정직히 병기(과대주장 회피).
- **R4 외부 링크 유지보수** — 큐레이션 링크가 죽을 수 있음(EBS 개편 등). 상위 개념 소수부터, 점검 주기 필요.
- **R5 기존 Vue 리디자인 자산 폐기** — [Design] P0/P1 코드가 React 재작성으로 대체됨. git 히스토리에 방향 전환 서사로 남겨 포폴 손실을 완화.
