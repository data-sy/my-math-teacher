# Milestone 7: 제품 피벗 — 자가진단 + 모바일 리디자인 (React)

> **상태: 📝 설계 초안 — 구현 미착수.** 라이브(M6) 서버 위에서 *서비스 미완의 근본 제약*(진단·맞춤이
> 의존하는 **문제 풀(problem pool)의 실부재**)을 우회하도록 **제품 정의 자체를 피벗**하는 마일스톤.
> 본 문서는 방향을 굳히는 설계 단계이며, 코드/프론트 변경은 §결정 사인오프 이후 spec-first 로 진행한다.

**결정일:** 2026-07-11 (사용자와의 방향 합의 세션)
**브랜치 정책:** spec 단위 분할(M2·M4·M6 관습). 착수 시 `feat/m7-spec-01-*` 부터.
**의존성:**
- **M6(라이브)** — `my-math-teacher.com` 상시 배포 위에서 프론트만 교체한다. 정적 `dist/`를 nginx 가 서빙하는 구조라 **blue-green·SSM·Terraform·TLS 무변경**(React 전환이 배포 레이어를 안 건드림).
- **M2(완료)** — 그래프 순회(`knowledge_space` 재귀 CTE)가 새 진단 엔진의 핵심. self-report 로 가도 이 부분은 그대로 산다.
**위험 수준:** **중간** — 앱 로직·인프라가 아니라 **프론트 전면 재작성 + 진단/맞춤 의미론 변경**. 백엔드 그래프 엔진·배포·데이터는 보존되어 리스크가 프론트+일부 서비스 레이어로 격리됨.

## 왜 피벗인가 (문제 정의)

MMT 3기둥 = ① 지식그래프 시각화 · ② 진단 · ③ 맞춤학습지. **문제 풀 부재가 ②③ 공통 병목**이고 ①만 무관하다.

- 기존 ②진단 = 학생이 문제를 풀고 정오답을 채점 → DKT(TF Serving)가 취약점 추론. **서빙할 실제 문항이 없다**(기존 `items` 8,120건은 가라 이미지 + 저작권 제약으로 공개 서비스에 못 올림).
- 기존 ③맞춤 = 취약점에 맞춘 학습지 출제 → (원 의도: 다시 풀려 재진단하는 루프). **이것도 같은 문제 풀에 의존** → 원천적으로 막힘.

두 갈래(1. AI 로 문제 생성 / 2. 우회) 중 **품질 보장 불가로 1을 버리고 2를 택함.** 우회의 구체가 아래 결정들이다.

> 이 피벗은 로드맵 `[GTM] 컨설팅 어젠다`(2026-07-06) ①②③ 을 사용자 판단으로 선결정한 것이다.
> 컨설팅은 이후 검증·GTM 관점으로 수행하되, 제품 방향은 본 문서가 정본.

## 새 제품 루프 (종이 플로우)

```
홈(그래프 기반 자가진단 가치제안)
  → 영역 진입 (학교급/단원 선택으로 그래프 진입점 좁히기)
  → 그래프 적응형 문답  ← 화면 1개당 개념 1개, "알아요 / 몰라요"
      · 개념 이름 + 대표 예시(미니 그림/한 줄)
      · "알아요" → 그 아래 선수지식 가지 skip
      · "몰라요" → 그 개념의 선수지식으로 drill-down
  → 취약점 결과
      · 그래프 기반 시급도순 우선순위(무너진 토대)
      · 개념별 외부 학습 링크(EBS 등)  ← 학습지 출제 대체
```

MBTI식 "클릭하면 답에 따라 다음 화면이 갈리는" 흐름 = 지식그래프를 **테스트 엔진 자체**로 쓰는 것.

## 무엇이 바뀌고 무엇이 남나

| 영역 | 상태 | 내용 |
|---|---|---|
| 지식그래프 데이터 | **유지** | concepts 1,631 / knowledge_space 3,446 — 서비스 해자. 시드 그대로 |
| 그래프 진단 엔진 | **유지** | `knowledge_space` 재귀 CTE/BFS(`JdbcTemplateConceptRepository`, `ConceptService`). self-report 에서 "모른다 개념 → 선수지식 순회"로 그대로 재사용 |
| 백엔드·인증·인프라 | **유지** | Spring/OAuth/MySQL/Redis, M2·M4·M6 배포(blue-green·SSM·Terraform·nginx 정적 서빙) 무변경 |
| answers/probabilities 스키마 | **유지** | 진단이 규칙기반으로 채우면 맞춤(`ItemService`) 소비 로직도 재사용 가능 |
| 프론트(`web/`) | **전면 재작성** | Vue → **React**, 모바일 퍼스트. 단 *줄어든 새 제품*(홈·문답·결과+로그인/에러) 기준 |
| 진단 입력 | **변경** | 문제 풀이·정오답 채점(`RecordView` o/x) → **self-report OX**(개념 알아요/몰라요) |
| 시급도 산출 | **변경** | DKT 퍼센트 → **그래프 기반 시급도**(막는 하위개념 수·깊이·수렴도, 설명가능) |
| 맞춤 출력 | **변경** | 학습지 출제 → **개념별 외부 학습 링크 큐레이션** |
| 홈 카피·포지셔닝 | **변경** | "AI 가 진단" → **"지식그래프 기반 자가진단 + 학습 가이드"** |
| DKT / TF Serving | **재움(삭제 X)** | `ProbabilityService.getPrediction`·`AnswerService.findAIInput`·`probabilityList[skillId-1]` 는 정오답 시퀀스에 강결합 → self-report 와 의미론 충돌. 플래그로 파킹, **실제 문항 확보 시 부활**(YAGNI: 미래 브릿지는 지금 안 짓고, 검증된 자산은 안 지운다) |

## 결정 (2026-07-11 사인오프)

- **D1 — 진단 = self-report OX.** 문제 풀 부재 우회. "정오답"을 "안다/모른다"로 대체. *근거:* 서빙 가능한 실문항이 없음.
- **D2 — 진단 엔진 = 그래프 적응형 문답(B안).** 개념 나열형(A안)이 아니라 답에 따라 경로가 갈리는 그래프 순회. 개념 1,631개를 다 못 묻는 문제를 "알아요→하위 skip"으로 해소해 화면 수를 짧게 유지. *A/B 프로토타입 비교는 착수 시 열어두되 B 에 무게.*
- **D3 — 시급도 = 그래프 점수(DKT 퍼센트 폐기).** DKT 에 self-report 를 먹이면 shape 은 맞아도 의미론상 garbage-in → "가짜 정밀도". 대신 그래프에서 ①막는 하위개념 수 ②깊이(근본성) ③여러 미지 개념의 수렴 뿌리 로 시급도 산출. 설명가능하고 문항·모델 불필요.
- **D4 — 맞춤 = 외부 링크 큐레이션.** 학습지 출제 제거. 개념별 EBS 등 외부 무료 자료 링크로 "어디서 이걸로 공부해" 까지 루프를 닫음. 상위 취약 개념부터, 전 개념 채울 필요 없음.
- **D5 — 문답 카드 = 개념 이름 + 대표 예시.** 이름만이면 "내용은 아는데 이름을 몰라" 오답 유발(자기보고 고질병) → 인식용 미니 예시 동반.
- **D6 — 기술 스택 = React 전면 전환(`web/`).** 커리어 수요(React) + 어차피 크리티컬 패스를 새로 그리는 지금이 전환 최저비용 시점. 백엔드·배포·그래프 데이터 무변경. → **기존 [Design] "React 이주는 launch 후" 결론을 supersede**(아래).
- **D7 — 모바일 퍼스트.** 기존 반응형이 깨지는 옛 Vue 템플릿을 폐기, 모바일 UX 기준으로 재설계.
- **레포 = 모노레포 유지(새 레포 X).** 라이브 백엔드·배포·그래프 데이터·M2/M4/M6 포폴 서사를 버리지 않음. "새로 시작하는 해방감"은 프론트 fresh 리빌드로 얻고, 방향 전환은 M7 히스토리로 남김.

### 기존 [Design] 트랙과의 관계 (supersede 명시)

로드맵 `[Design] 실배포 전 리디자인`(2026-06-23)의 결론은 **"launch 까지 Vue 유지 + React 이주는 launch 후 재검토"** 였다. M7 이 이를 갱신한다: **self-report 피벗으로 프론트를 어차피 새로 그리게 되어, React 전환을 이 리디자인과 합쳐 지금 수행**한다. 그 트랙의 P0/P1 산출물(히어로·결과 재설계·셸·토큰·폼 등, 전부 Vue)은 **UX 결정은 재사용**하되 **코드는 React 재작성으로 대체**된다.

## 구성 spec (착수 시 spec-first 작성)

아직 미작성. 착수 시 아래로 분할 예정(분할은 착수 시 확정):

- **spec-01 — 진단 엔진(백엔드):** self-report 문답 진행 + 그래프 적응형 순회 + 시급도 점수(D1·D2·D3). DKT 파킹 플래그.
- **spec-02 — 프론트 React 전환 + 모바일 크리티컬 패스:** 홈·문답·결과(+로그인/에러). 스캐폴딩(Vite React·상태관리·UI 라이브러리), Cytoscape/Chart.js/html2pdf 포팅(프레임워크 무관).
- **spec-03 — 맞춤 링크 큐레이션(D4):** 개념별 외부 링크 데이터 + 결과 화면 노출.

## 리스크 레지스터

- **R1 자기보고 정확도** — 학생 과대평가 위험. 완화: D5(이름+예시), 그리고 "인증"이 아니라 "자가진단 학습 가이드"로 정직하게 프레이밍.
- **R2 React 전면 재작성 스코프** — auth/OAuth 인터셉터·router·`api.js`·레이아웃·PrimeVue 가 전부 Vue → 재작성 대상. 완화: 피벗이 앱을 **줄여**(무거운 진단·학습지 출제·DKT 화면 제거) 재작성 표면이 현행보다 작음. 백엔드/인프라 무변경으로 리스크 격리.
- **R3 포지셔닝 변경("AI 진단" 간판 내림)** — 이력서/포폴 문구 정합 필요(GTM 어젠다 ②). DKT 는 재워둔 것이라 "문항 확보 시 부활" 서사 유지 가능.
- **R4 외부 링크 유지보수** — 큐레이션 링크가 죽을 수 있음(EBS 개편 등). 상위 개념 소수부터, 점검 주기 필요.
- **R5 기존 Vue 리디자인 자산 폐기** — [Design] P0/P1 코드가 React 재작성으로 대체됨. git 히스토리에 방향 전환 서사로 남겨 포폴 손실을 완화.

## 검증(착수 후)

- self-report 문답이 그래프 경로를 실제로 갈라 화면 수를 줄이는지(적응형 동작).
