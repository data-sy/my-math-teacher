# [백로그] ④-B 스테일 큐 — 첫 토글 403 후 자가치유 (1탭 손실 UX)

> 등록 2026-07-18 · 출처 = 실기기 시각검증 2차(iPhone, 오류 코드 403 수거) → 스테일 큐 재현·원인 특정 (e2e 회귀 `flows.spec.ts` "④-B 스테일 큐 403" 고정)

## 현상

④-B(저장 결과) 화면이 **옛 큐의 스냅샷**인 상태에서 체크리스트를 토글하면, 이미 대체된 옛 queueId 로 PATCH 가 나가 403("찾을 수 없어요") — 인라인 에러 스트립이 한 번 뜨고, 자가치유(실패 시 큐 재조회) 후 재탭부터 정상.

## 실서비스에서도 발생하나 — **발생한다 (mock 전용 아님)**

활성 큐 = 유저당 1개(새 귀속이 대체)는 실서버 계약이므로, 화면 스냅샷이 stale 해지는 경로가 있으면 동일하게 난다:

- 같은 폰에서 ④-B 를 띄워둔 채 → 재진단·재귀속 → 뒤로가기/탭 복귀(bfcache 스냅샷)로 옛 ④-B 에서 토글
- 두 탭·두 기기에서 같은 계정 사용 (한쪽에서 재귀속 → 다른 쪽 화면 stale)

빈도는 낮고(재귀속 사이에 옛 화면을 다시 여는 경우 한정), 데이터 손상은 없음 — 손실은 "첫 탭 1회 + 에러 스트립 노출" 뿐.

## 현재 완화 (2026-07-18 반영분 — 런치 블로커 아님 판단 근거)

- 토글 실패 시 `['queue','me']` invalidate → 목록이 현재 큐로 자동 갱신, 재탭 성공 (e2e 고정)
- TanStack Query `refetchOnWindowFocus` 기본 on — 탭/앱 복귀 시 백그라운드 재조회가 대개 선제 치유
- 전 API 15s 타임아웃 + 에러 스트립 원인 코드 표기

## 착수 시 할 일 (첫 탭 실패 자체를 없애기)

- 후보 A(최소): 플로팅 pill 탭(시트 열기) 시점에 큐 invalidate — 토글 가능 시점 전에 최신화, 레이스 창 대폭 축소
- 후보 B: `pageshow`(persisted)/`visibilitychange` 훅으로 bfcache 복귀 감지 시 즉시 재조회 (iOS 스냅폭 복귀 커버)
- 후보 C: 토글 응답이 갱신된 큐 전체이므로(실측), 403 시 1회 자동 리트라이(재조회 후 대응 위치 항목으로) — 단 "자동 재시도 = 사용자 의도 보존" 검증 필요 (position 이 바뀌었을 수 있음 → 잘못된 항목 체크 위험. A/B 우선 권장)
