# [Backend] 자바 17 상향 — Spring Boot 3.1.6 동반 상향이 전제

- **상태:** ⬜ 미착수
- **등록:** 2026-09-08 (mothball 정리 중 사용자 지시로 등록)
- **인프라 불요** — 휴면(2026-09~) 중에도 진행 가능한 몇 안 되는 항목이다. 검증 표면이 전부 로컬·GitHub 러너다(아래 §검증).

## 지금 무엇으로 굳어 있나 (실측 2026-09-08)

| 지점 | 현재 값 |
|---|---|
| `api/build.gradle` | `sourceCompatibility = '17'` · Spring Boot **3.1.6** · dependency-management 1.1.4 |
| `api/Dockerfile` | 빌드 `gradle:8.4-jdk17` · 런타임 `amazoncorretto:17-alpine` |
| `.github/workflows/api-ci-cd-with-ec2.yml` | `java-version: '17'` |

**네 곳을 함께 옮겨야 한다.** 하나라도 빠지면 로컬은 초록인데 이미지가 다른 JVM 으로 뜨는 어긋남이 된다.

## 왜 (급하진 않지만 유통기한이 있다)

- **자바 17 자체는 아직 유효하다** — Corretto 17 지원은 2027-10 까지. 이 항목의 압력은 자바가 아니라 **Spring Boot** 쪽이다.
- **Spring Boot 3.1.x 는 이미 OSS 지원이 끝났다**(2024-05). 지금 받는 보안 패치가 없다. 그리고 최신 Boot 로 올리려면 자바 하한이 함께 올라가므로, **"자바만 올리기"는 성립하지 않고 두 축이 한 작업**이다.
- 순서 함정: 자바만 먼저 올리면 Boot 3.1.6 이 새 JVM 에서 뜨는지가 별도 리스크가 된다. **Boot 를 목표 버전으로 정하고 그것이 요구하는 자바를 따라가는** 방향이 맞다.

## 착수 시 먼저 정할 것 (트레이드오프 — 사용자 결정)

목표 조합을 먼저 확정한다. 최신을 무조건 집는 게 아니라, 이 리포가 감당할 이행 폭으로 고른다.

- **보수적:** Boot 3.3/3.4 + 자바 21 LTS — 이행 폭이 좁고 자료가 많다
- **최신:** Boot 3.5+ + 자바 25 LTS — 지원 기한이 길지만 한 번에 건너는 폭이 크다

정하고 나면 Boot 마이그레이션 가이드의 breaking change 를 훑어 영향 지점을 먼저 조사한다(`/analyze-before-change`).

## 검증 (인프라 없이 닫히는 것까지가 이 항목의 범위)

1. `cd api && ./gradlew test` — 전체 스위트 **181/0** 이 기준선(2026-08-31 달성치). Testcontainers 쓰므로 Docker 필요.
2. **CI `tests_only` 실행** — 워크플로 `if: ${{ !inputs.tests_only }}` 로 build-and-push·deploy 가 스킵되므로 **AWS 자격·인프라 없이** 게이트만 돈다. 휴면 중 CI 초록을 확인할 수 있는 이유다.
3. **로컬 `bootRun` 실측** — 단위 테스트는 생성자를 직접 부르므로 Spring DI 배선 실패를 못 잡는다. Boot 메이저 상향은 배선이 깨지는 전형적 지점이라 **실기동까지 봐야 끝**이다.
4. 이미지 빌드 확인은 재런치 때로 미룬다(배포 표면이 없으므로).
