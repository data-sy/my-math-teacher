# [백로그] knowledge_space 상호선수 2-사이클 26쌍 데이터 정비

**등록:** 2026-07-14 (spec-01 완성물 리뷰 residual ① — 사인오프에서 "백로그" 확정, launch 비차단)
**성격:** 콘텐츠·데이터 정비 (코드 아님) — spec-03 콘텐츠 트랙(링크 큐레이션)과 같은 성격의 사람 판단 작업
**실측 기준:** 2026-07-13, 로컬 mmt DB (간선 3,446 · 개념 1,631)

## 문제

`knowledge_space` 에 A↔B 상호선수 2-사이클이 **26쌍(간선 52, 관여 개념 43)** 존재한다.
선수 그래프는 DAG 여야 하며, 사이클은 데이터 입력 오류다.

## 방치 시 실증상 (수치)

- **문답(§4.3):** 페어 한쪽에 "알아요" → 반대쪽이 자동 inferred-known 처리되어 질문 생략.
  실제로 모를 수 있는 개념이 건너뛰어짐 — 43개 개념 국소.
- **학습 큐(§4.6):** depth≤3 확장에 페어가 통째로 들어오는 시작 개념 **302/1,631(18.5%)** 에서
  위상정렬 degrade(간선 drop) 발동 가능 → 그 두 계단의 순서가 교육적 보장 없이 임의.
  (구현은 죽지 않음 — Kahn 강제 진입 + 경고 로그. 2026-07-13 E2E 큐 14개에서 위반 0.)
- **blockedDescendants(§4.5):** 상호 부풀림은 depth 3 캡으로 미미.
- 참고: 폐쇄에 사이클 멤버를 포함하는 개념은 816/1,631 — 단 증상은 페어 내부 상호추론에 국한.

## 관측

- 현재 유일한 관측 수단 = `LearningQueueService` 의 "사이클 감지 — 강제 진입" **경고 로그**.
  M5 관측성 착수 시 카운터(메트릭) 노출 권고.

## 정비 절차 (착수 시)

1. 백업: `SELECT * FROM knowledge_space WHERE (from_concept_id, to_concept_id) IN (<52간선>)` 덤프 1줄 — 가역 확보.
2. **쌍마다 사람 판단 26건**: 어느 방향이 진짜 선수인가. 동단원·동명 쌍이 많아 자동 규칙(저학년=선수) 불가.
   - 예: 7805↔7806 "10을 만들어 더하기"(동명, 차시만 다름), 7601↔7602 "0이 있는 덧셈/뺄셈".
   - ⚠️ 클러스터 단위 정리 필요(쌍 단위 아님): {7805,7806,7813} · {8094,8095,8096,8097} · {8123,8124,8127} · {8130,8131,8132,8133}.
3. 방향 확정 후 역방향 26행 DELETE (또는 양방향 모두 오류면 52행).
4. 재검증: 2-사이클 카운트 0 확인 + `graph:v2:` Redis 캐시 무효화 + 스냅샷 재생성(shared/benchmark).

재현 쿼리(카운트):
```sql
SELECT COUNT(*) FROM knowledge_space a
JOIN knowledge_space b ON a.from_concept_id=b.to_concept_id AND a.to_concept_id=b.from_concept_id
WHERE a.from_concept_id < a.to_concept_id;
```
