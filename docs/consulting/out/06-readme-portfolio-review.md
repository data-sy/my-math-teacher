> ### ❌ 아래 부수 발견은 **오독이었다 — 2026-08-13 철회**
>
> 재런치 핸드오프의 실물 기록으로 확정: mothball(2026-07-31)에 EIP release(반환 `54.116.29.102`) + A레코드 삭제가 **실제로 수행됐고**, 재런치(2026-08-05)에 새 EIP `15.164.145.106` 로 A레코드를 **재생성**했다. 아래에서 관측한 "죽은 IP 를 가리키는 레코드" 는 **재런치 진행 중**(certbot 이 DNS 를 선행 요구해 A레코드를 먼저 붙이고 호스트는 아직 기동 전) 구간을 밖에서 본 것이다. **ROADMAP 서술이 옳았고, dangling DNS 위험은 없었다.** 원문은 검수 당시 판단 기록으로 남긴다.
>
> **부수 발견 (README 밖 · 즉시 조치 권고, 이 검수에서 자동 수정하지 않음):**
> `www.my-math-teacher.com` 의 A 레코드가 **Route53 권위 응답에 아직 살아 있다** — `dig @ns-114.awsdns-14.com. www.my-math-teacher.com A` → `15.164.145.106`(TTL 300). 그런데 이 IP는 80·443 모두 무응답이다. ROADMAP.md:16은 *"DNS `www` A레코드 삭제 ✅ 완료 (2026-07-31)"* 라고 기록하고 있고, 반환된 IP를 `54.116.29.102` 로 적었다 — **현재 레코드가 가리키는 IP와 다르다.** 즉 로드맵이 삭제 이유로 든 위험(*"반환된 IP가 타 계정에 재할당되면 내 도메인으로 남의 서버가 서빙"*)이 **지금 실재하는 상태**다. 공개 레포 + 이력서에 적힌 도메인이라 위험이 더 크다. Route53 호스팅 존을 직접 확인하고, 로드맵의 "삭제 완료" 서술도 실제 상태에 맞게 정정할 것을 권한다. (외부 인프라 변경이라 사용자 트리거가 필요 — 본 세션에서 손대지 않았다.)

| **3** | **M-1 목차 삭제 + 헤더 블록 신설** | 섹션 재작성 (약 20줄) | T1 예산을 통째로 회수한다. 새 자료가 전혀 필요 없는 순수 재배치인데 첫인상이 가장 크게 바뀐다. |
| **4** | **M-3 + M-2 하이라이트에 M7·M6 추가** | 섹션 재작성 (약 40줄, 자료는 이미 존재) | 최근 6개월 성과 전체가 여기서 복구된다. 근거 문서(ADR-0012, m7-r2 벤치마크, milestone-6)가 이미 다 있어 작성만 하면 된다. |
| **5** | **C-5 "개발 중" 삭제 + C-7 11.3→11.4** | 줄 단위 수정 (4줄) | "개발 중" 세 글자가 프로젝트를 미완성으로 낙인찍는다. 수치 정정은 대조 검산을 통과시킨다. 둘 다 5분. |

> 이미지 교체(C-2·C-3)와 ERD 재생성(C-6)은 **신규 자료가 필요**해 Top 5 밖에 뒀다. 다만 교체 자료를 만들기 전까지는 **이미지를 빼두는 편이 현재 상태보다 낫다** — 잘못된 화면을 보여주는 것보다 안 보여주는 편이 감점이 적다.

## ⑦ 열린 결정 (사용자가 정해야 함)

어시스턴트가 임의로 정하면 안 되는 트레이드오프다. 각 항목에 권장안과 근거를 붙였다.

### O-1. 서비스 링크를 어떻게 쓸 것인가

| 옵션 | 내용 | 트레이드오프 |
|---|---|---|
| **A (권장)** | 하이퍼링크 제거 → **상태 서술로 강등** + 데모 이미지/GIF로 대체 | 죽은 클릭이 사라진다. "라이브 서비스" 타이틀은 잃는다. |
| B | 링크 유지 + 경고 문구 강화 | 도메인 보유는 보여주지만 **클릭 실패가 문구보다 먼저 온다** — 실패 지점이 그대로 남는다. |
| C | 재런치해서 살림 (`terraform apply` → 스냅샷 restore → DDL 적용 → 새 EIP·DNS) | 라이브 링크 회복. 비용 재개(~월 $37) + 재런치 절차 실행 부담. |

**권장 = A.** 근거: 죽은 링크는 "과장"과 같은 등급의 감점이다(§8). 반면 "비용 판단으로 껐고 재런치 절차가 문서화돼 있다"는 서술은 **손실 없이 판단력으로 전환**된다. 다만 면접 일정이 확정돼 있고 그 기간만 살릴 수 있다면 C가 A보다 강하다 — **면접 일정 유무가 이 결정의 실제 변수**다.

### O-2. 피벗·폐기 서사를 어디까지 노출할 것인가

| 옵션 | 내용 |
|---|---|
| **A (권장)** | 「제품 판단 기록」 섹션으로 **적극 노출** — 근거·측정·대안 검토까지 |
| B | 하이라이트 안에 한 줄씩만 담담히 언급 |
| C | 노출하지 않고 최신 상태만 서술 |

**권장 = A.** 근거: §1 페르소나 전제대로 *"실패·후퇴·폐기 결정을 근거와 함께 적은 README는 강한 신호이고, 숨긴 흔적이 보이면 역효과"* 다. 그리고 이 저장소는 **숨길 수가 없다** — 공개 레포에 ROADMAP.md·ADR 14건이 그대로 있어서, README만 매끈하면 오히려 불일치가 드러난다. C는 실행 불가에 가깝다.

### O-3. README를 하나로 갈 것인가, 쪼갤 것인가

| 옵션 | 내용 |
|---|---|
| **A (권장)** | 루트 README = 포트폴리오용, 로컬 셋업 → `docs/DEVELOPMENT.md` 분리 |
| B | 현행 단일 유지, 셋업을 `<details>` 접기로 |
| C | 완전 분리 (`README.md` + `README-dev.md` 동급) |

**권장 = A.** 근거: §3의 두 독자 충돌에서 제1 독자 우선 원칙. 74줄(32%)이 회수된다. B는 접어도 스크롤 위치를 차지하고, GitHub 모바일에서 `<details>` 렌더링이 고르지 않다.

### O-4. 이미지 자산을 어떻게 처리할 것인가

| 옵션 | 내용 | 비용 |
|---|---|---|
| **A (권장)** | 아키텍처 다이어그램 재작성 + 제품 스크린샷은 **web-v2 캡처로 교체** | 다이어그램 1장 신규 + 캡처 재사용(2026-07-18 시각검증 산출물 13장 존재) |
| B | 이미지 전량 제거, 텍스트만 | 즉시 가능·감점 제거. 그러나 T1에서 "무엇을 만들었나"의 시각적 각인을 잃는다 |
| C | 아키텍처만 고치고 제품 스크린샷은 v1 유지 + `(v1 화면)` 라벨 | 저비용이나, 라벨 붙은 구 화면은 "현재 화면은 왜 없지?"를 부른다 |

**권장 = A, 단 자료 준비 전까지는 B로 임시 조치.** 근거: 잘못된 화면은 안 보여주는 것보다 감점이 크다(C-2·C-3). 그리고 web-v2는 프로덕션에 스왑되지 않았으므로 **"이건 아직 배포 전 화면"** 이라는 라벨을 붙일지 여부가 A 안에서 또 하나의 선택지다 — 이건 O-2(피벗 노출 수위)와 함께 정해야 한다.

### O-5. 하이라이트를 몇 개로 둘 것인가

현재 2개(M2·M4) → 제안대로면 4개(M2·M4·M6·M7). **T2 예산 3분 안에 4개는 과하다.**

| 옵션 | 내용 |
|---|---|
| **A (권장)** | 3개로: **M7(제품·알고리즘) · M4(무중단) · M2(DB 통합)** + M6은 M4 항목 안에 "상시 운영으로 소비" 2줄로 흡수 |

| C | 2개 유지(M7 · M4)하고 M2·M6은 문서 지도 링크로 |

**권장 = A.** 근거: M6은 M4의 소비처라 서사가 자연스럽게 이어지고, 독립 항목으로 세우면 "배포" 주제가 두 번 반복돼 T2에서 지루해진다. 다만 **지원 포지션이 인프라 쪽으로 더 기운다면 M6을 독립시키고 M2를 강등하는 편이 낫다** — §0의 포지션 값을 확정해주면 이 순서를 다시 잡겠다.

### O-6. 영문 README 필요 여부

현재 국문 단일. 시각 리포트는 KO/EN 양쪽이 있다(`milestone-4-zero-downtime-report-{ko,eng}.html`).

**권장 = 지금은 불필요.** 근거: §0 기본값이 국내 서비스 기업 지원이다. 영문화는 국문 README가 최신화된 **다음**에 할 일이고, 지금 착수하면 stale 서술을 두 벌로 늘린다. **외국계·해외 지원 계획이 있다면 알려달라 — 그 경우 우선순위가 바뀐다.**
