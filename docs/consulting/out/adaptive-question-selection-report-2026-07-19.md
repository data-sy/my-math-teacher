# 적응형 문항 선택 알고리즘 컨설팅 결과

> 실행 프롬프트: `🤖-문항-선택-알고리즘-컨설팅.md` · 정본 백로그: `docs/backlog/m7-adaptive-traversal-question-selection.md` · 실행일: 2026-07-19

## ① 서베이 (계열별)

**1. KST 계열 (지식공간이론 — ALEKS 식)**
학생의 지식 상태를 "선수관계를 존중하는 개념 부분집합"으로 보고, 가능한 상태들의 공간을 질문으로 좁혀 간다. 핵심 선택 원리는 이분 탐색과 같다: 답이 "알아요"든 "몰라요"든 남은 상태 공간을 가장 균등하게 가르는 개념부터 묻는다. ALEKS 는 상태별 확률 분포를 갱신하는 확률적 버전을 쓰지만, 결정론적 근사 — "미확정 영역에서 선수 폐쇄 크기와 후수 폐쇄 크기가 균형인 개념 우선" — 만으로도 원리 있는 질문 순서가 나온다. 본 서비스의 DAG 와 개념적으로 동형이라 이식이 가장 자연스럽고, 구조만으로 작동하므로 사용자 데이터 0에서도 유효하다. 단, 정확한 상태 공간 계산은 지수적이라 프록시 설계가 필요하며 2주 내에는 근사 형태만 가능.

**2. CAT/IRT 계열**
능력치 θ를 추정하면서 Fisher 정보량이 최대인 문항을 고르는 고전적 적응 검사(SAT·GRE 계열). 전제는 문항 모수(난이도·변별도)의 사전 보정 — 문항당 수백 건의 실응답이 필요하다. **실사용자 0인 현 상태에서는 모수가 존재하지 않아 즉시 적용 불가.** 학년·단원 깊이로 난이도를 지어내면 그것은 IRT 가 아니라 휴리스틱에 라벨을 붙인 것. "데이터가 쌓인 뒤"의 후보로만 유효.

**3. DKT 역이용**
이미 떠 있는 DKT(TF Serving)에 현재까지의 답변 시퀀스를 넣으면 개념별 예측 확률 p가 나온다. 활용 두 갈래: (a) p가 0.5에 가까운(불확실성 최대) 개념부터 묻기, (b) "알아요"로 skip 된 폐쇄 안에서 p가 낮은 개념을 검증 질문으로 뽑기. 추가 인프라 0, 같은 입력 → 같은 출력이므로 모델 버전을 고정하면 결정론 유지 가능. 리스크는 둘: 순회 중 매 스텝 원격 호출 지연(+서빙 다운 시 폴백 필요), 그리고 DKT 가 실제 문제풀이 데이터로 학습됐는데 자가보고 OX 를 먹이는 분포 불일치(예측 품질 미검증).

**4. 밴딧/탐색-활용 계열**
질문 선택을 arm 으로 보고 보상 신호(진단 후 학습 지속·재방문 등)로 정책을 학습한다(Duolingo 연습 세션 구성이 대표 사례). 다수 사용자의 보상 로그가 필수인데 런치 전 0명이라 학습할 것이 없고, 확률적 정책은 결정론 계약과 정면충돌(시드 고정으로 우회 가능하나 얻는 게 없음). 런치 후 휴리스틱 파라미터 튜닝 용도로나 재검토.

**5. 휴리스틱 강화 (가장 싼 안)**
현행 규칙 유지 + 3개 패치: (a) 최소 질문 수 하한 — 미달이면 종료하지 않고 검증 질문을 계속 뽑음, (b) "알아요" 폐쇄 skip 을 "잠정 앎 + 폐쇄 내 프로브(탐침) 1~2개"로 완화 — 프로브가 틀리면 해당 영역 복원, (c) 후보 순서를 conceptId 대신 blockedDescendants(그 개념이 막고 있는 후수 개수) 내림차순으로. 전부 그래프 구조에서만 계산 → 콜드스타트 무관·결정론·stateless 그대로. 사실상 KST 의 결정론적 축약판.

## ③ 판별 질문 (≤3)

**Q1. 오진 방지 vs 3분 체감, 충돌하면 무엇을 우선하나?**
"과대평가 학생이 질문 1~3개로 '약점 없음' 판정받는 것"을 막는 데 질문 몇 개를 더 쓸 수 있는가. → 정확도 우선이면 프로브 밀도↑·KST 근사까지, 체감 우선이면 휴리스틱 최소 패치(프로브 1개·하한 낮게).

**Q2. 순회 중 매 답변마다 TF Serving 호출을 허용하나?**
스텝당 수십~수백 ms 지연 + 서빙 다운 폴백 규칙 필요 + preview–저장 동치를 위한 모델 버전 고정 전제. → 허용이면 2단계에서 DKT 역이용으로 업그레이드, 불허면 구조 기반(휴리스틱/KST 근사)에 머문다.

**Q3. 프로브가 틀렸을 때("알아요"라던 폐쇄에서 검증 실패) 어디까지 되돌리나?**
그 프로브 개념의 하위트리만 복원(질문 수 절약) vs 원래 skip 한 폐쇄 전체 복원(오염 최소화). 학생의 자가보고를 얼마나 의심하는 서비스인가의 제품 톤 문제이기도 함. → 전자면 3분 계약이 안전, 후자면 정확도가 안전.

## ④ 권장안 + 단계적 채택 경로

**권장: 1단계 = 휴리스틱 강화(KST 원리 차용), 2단계 = DKT 역이용으로 키 교체, IRT·밴딧은 실데이터 이후로 보류.**

### 1단계 (지금, 수일 규모) — spec-01 §4.3 변경점

- **R1(알아요 → 선수 폐쇄 전체 skip) → "skip-with-probe"로 교체**: 폐쇄는 "잠정 앎"으로만 표시하고, 폐쇄 내 blockedDescendants 최대 개념 1개(폐쇄 크기가 임계 m 이상이면 2개)를 검증 질문으로 후보 큐에 남긴다. 프로브 "몰라요" → Q3 답에 따라 그 개념의 직계 선수(최소) 또는 폐쇄 전체(최대)를 복원.
- **종료 규칙(후보 소진 = 종료) → 하한 추가**: 답변 수 < K(예: 5)이면 종료하지 않고 잠정-앎 영역에서 추가 프로브를 뽑아 계속. 후보와 잠정 영역이 모두 소진됐을 때만 조기 종료 허용. → 결함 1 해소.
- **순서 규칙(conceptId 오름차순) → blockedDescendants 내림차순, 동률 시 conceptId** (결정론 tie-break 유지). → 결함 3 해소.
- **상한 신설**: 질문 수 ≤ N(예: 20) 하드캡 — 3분 계약 보전.

### 2단계 (런치 후, Q2가 '허용'으로 답해지면)

- 순서 키만 blockedDescendants → **DKT 불확실성 \|p−0.5\|** 로 교체 (tie-break 규칙 동일 유지).
- 프로브 선정을 "폐쇄 내 blockedDescendants 최대" → "폐쇄 내 p 최저"로 교체.
- 종료 조건에 "모든 미질문 개념의 p가 신뢰 임계 밖" 보강.
- 전제: 모델 버전 고정 + 서빙 다운 시 1단계 규칙으로 자동 강등(결정론 계약을 "모델 버전 포함 입력이 같으면 같음"으로 재정의).

### 3단계 (실응답 수천 건 축적 후)

- 자가보고 OX 로그로 개념별 응답 통계를 쌓은 뒤, IRT 보정 또는 밴딧식 파라미터 튜닝(K·m·N 상수를 데이터로 대체)을 재평가.

### 권장 근거

결함 3건이 전부 1단계에서 그래프 구조 계산만으로 해소·완화되고, 아키텍처 계약 4종(stateless·결정론·3분·API/화면 불변)을 하나도 건드리지 않으며, 2단계가 1단계 규칙의 "정렬 키 교체"라 마이그레이션이 국소적이다. 유일하게 감으로 정하는 상수(K·m·N)는 3단계에서 데이터로 대체하는 경로가 열려 있다.
