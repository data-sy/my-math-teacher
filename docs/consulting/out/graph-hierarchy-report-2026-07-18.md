# 그래프 위계 백지 컨설팅 — 결과 리포트

> 2026-07-18 · 입력: `../04-graph-hierarchy-consult.md` · 목업: [graph-hierarchy-mockup.html](graph-hierarchy-mockup.html)
> 의도적으로 현행 팔레트·기존 스타일 정보 없이 백지에서 설계. 현 디자인 시스템으로의 맵핑은 별도 후속 단계.

## ① 상태 공간 정의

시스템 전역은 2모드다: **무선택 모드**(전 노드 중립 단일 톤·균일 크기 — 상태 분화 없음)와 **선택 모드**(탭 직후). 선택 모드의 노드 상태는 **6개가 적정**하다.

| # | 상태 | 정의 | 답하는 질문 |
|---|------|------|------------|
| 1 | 선택 | 탭한 노드 (항상 1개) | 기준점 |
| 2 | 선수-직접 | 선택으로 들어오는 엣지의 출발 노드 (뎁스 −1) | Q1 토대 + Q3 직접 |
| 3 | 선수-원거리 | 뎁스 −2 이하 **전부 병합** | Q1 토대 + Q3 간접 |
| 4 | 후수-직접 | 뎁스 +1 | Q2 열림 + Q3 직접 |
| 5 | 후수-원거리 | 뎁스 +2 이하 **전부 병합** | Q2 열림 + Q3 간접 |
| 6 | 계보 밖 | 선수·후수 경로에 속하지 않는 노드 | 지형 (숨기지 않고 후퇴) |

**왜 뎁스별 8~9개가 아니라 6개인가:**
- 직접/원거리 이분법이 질문 3("직접인가 간접인가")의 답 그 자체다. 학습자의 다음 행동은 "바로 옆 노드를 볼까"이므로 뎁스 −2와 −3의 구분은 행동을 바꾸지 않는다.
- 소화면 제약: 9~11px 노드에서 같은 hue의 명도 3스텝은 병치 비교 없이(절대 판단으로) 판별 불가. 상태 수는 "판별 가능한 시각 스텝 수"에 맞춰야 하고, 그 상한이 방향당 2스텝이다.
- 단, 병합은 **공식 상태**의 병합이다. 크기 같은 연속 채널은 뎁스를 따라 계속 줄여 원근감을 유지해도 된다(상태 6개 + 연속 보조 채널 자유).

**엣지 상태는 3개**(+방향 속성):

| # | 상태 | 정의 | 방향 표시 |
|---|------|------|----------|
| 1 | 직접 엣지 | 선택 노드에 인접한 in/out 엣지 | 화살촉 필수 |
| 2 | 계보 내 원거리 엣지 | 선수끼리·후수끼리 잇는 경로 엣지 | 화살촉 유지 |
| 3 | 계보 밖 엣지 | 나머지 전부 (계보↔밖 경계 엣지 포함) | 화살촉 생략 (잉크 절약) |

## ② 채널 배정 원칙

| 정보 변수 | 성격 | 배정 채널 | 근거 |
|----------|------|----------|------|
| 선택 여부 | 이진·초점 | **크기(최대) + 명도 극단 + 이중 링/할로** | 크기는 가장 강한 전주의 채널이면서 줌과 함께 스케일 — 줌아웃에도 초점 유지. 링은 로컬 대비라 어떤 배경색 위에서도 작동. 터치 타깃 확대 겸용 |
| 방향 (선수/후수) | 범주 2값·순서 없음 | **hue(범주형)** 또는 **위치(공간)** | 범주형 변수엔 범주형 채널. 명도로 방향을 나누면 "선수가 더 중요"라는 거짓 순서가 생긴다. 난색 금지 제약 → 한난 대비 대신 냉색 2종(teal↔violet), CVD 시뮬레이션 검증 통과 |
| 거리 (직접/원거리) | 순서형 | **명도·채도 (+크기 보조)** | 순서형 변수엔 순서형 채널. hue로 거리를 표현하면 무지개가 된다. "옅다=멀다" 은유가 소화면에서 가장 저렴 |
| 계보 여부 | 이진·배경화 | **채도 붕괴(무채색화) + 크기 축소 + 라벨 감쇠** | "숨기지 않되 물러난다"의 정답은 투명도가 아니라 무채색화 — 투명도는 엣지 겹침에서 지저분해지고, 무채색은 지형을 남기며 시선만 뺏지 않는다 |
| 엣지 방향 | 범주 | **화살촉 (+노드 팔레트 상속)** | 호버 없는 터치 환경에서 방향은 항상 명시적이어야 한다. 색만으로 방향을 싣는 안은 탈락 |
| 라벨 | (채널이 아니라 자원) | 선택·직접 = 항상 > 원거리 = 축소 > 계보 밖 = 저줌에서 생략 | 라벨은 예산 배분 문제. Cytoscape `min-zoomed-font-size`로 줌 임계 구현 가능 |
| 모션 | 전이 전용 | 선택 전이 1회 200~250ms, 지속 애니메이션 금지 | 모션은 상태가 아니라 **상태 변화**를 설명하는 채널. 모바일 배터리·주의 비용 |

소화면·터치 제약 3줄 요약: ① 호버가 없으므로 모든 정보는 정적 인코딩 + 탭으로 도달 가능해야 한다. ② 크기 위계는 터치 타깃 위계와 정렬된다(중요한 노드가 누르기 쉽다). ③ 줌 의존 채널(라벨)이 위계의 유일한 운반자가 되면 안 된다.

## ③ 판별 질문 (≤3)

| # | 질문 | 답 → 기우는 콘셉트 |
|---|------|------------------|
| Q1 | **지도 항상성**: 탭할 때마다 그래프가 재정렬되어도 좋은가, 노드는 "제자리"에 있어야 하는가? | 재정렬 OK → **B** · 제자리 → **A/C** |
| Q2 | **색의 의미 예산**: 이 화면(또는 인접 화면)에서 색을 다른 의미(이해도 히트맵, 단원 구분)로 쓸 계획이 있는가? | 있다 → **C** · 없다 → **A** |
| Q3 | **원거리 방향 즉독성**: 먼 노드도 선수 쪽/후수 쪽이 색만으로 즉시 읽혀야 하는가, 지형만 보이면 되는가? | 즉시 → **A** · 지형만 → **B/C** |

## ④ 콘셉트 상세 스펙

### A. 색 층위 — Hue = 방향, 명도 = 거리 (좌표 불변)

| 상태 | 채움 | 테두리 | 반지름 | 라벨 |
|------|------|--------|--------|------|
| 선택 | `#0F172A` | 흰 3px + 외곽 링 1.5px + 할로 | 20px (할로 30px) | 12px·800 항상 |
| 선수-직접 | `#0D9488` | 없음 | 15px | 10.5px·700 항상 |
| 선수-원거리 | `#2FB5A6` | 없음 | 11px (뎁스3 9px) | 9px·500 |
| 후수-직접 | `#7C3AED` | 없음 | 15px | 10.5px·700 항상 |
| 후수-원거리 | `#A78BFA` | 없음 | 11px (뎁스3 9px) | 9px·500 |
| 계보 밖 | `#DCE1E8` | 없음 | 7px | 8px·400 저줌 생략 |

엣지: 직접 2.5px(선수 `#0D9488` / 후수 `#7C3AED`, 화살촉) · 원거리 1.5px(`#A5D8D2` / `#D4C6FD`, 화살촉) · 밖 1px `#E8EBEF` 무화살촉.

- **기대**: 세 진영이 색으로 즉독. 좌표 불변 → 공간 기억 유지. 모션 0.
- **리스크**: 원거리 라이트 톤은 대비 2.4~2.6:1 — 의도된 후퇴지만 라벨 보조 필수. teal·violet이 이후 브랜드 맵핑 단계에서 조정될 수 있음(hue 2종을 쓴다는 원칙만 유지하면 됨). 난색 미사용 → 경고 의미 충돌 없음.
- **구현**: Cytoscape 표준 스타일 속성(fill·border·width·label)만으로 가능. 선택 시 클래스 부여. 난도 하.

### B. 공간 재배치 — 위치 = 방향, 명도 = 거리 (탭 시 재정렬)

| 상태 | 채움 | 위치 | 반지름 | 라벨 |
|------|------|------|--------|------|
| 선택 | `#0F172A` | 중앙 밴드 | 20px | 12px·800 |
| 직접 (±1) | `#1D4ED8` | 선택 바로 위/아래 행 | 15px | 10.5px·700 |
| 뎁스 2 | `#3B82F6` | 그다음 행 | 11px | 9px·500 |
| 뎁스 3 | `#7EB3F5` | 최외곽 행 | 9px | 9px·500 |
| 계보 밖 | `#D6DBE1` | 좌우 가장자리 거터 | 7px | 7.5px·400 |

보조 장치: 밴드 배경 `#F3F7FC`, 밴드 캡션("토대 — 여기서 올라왔다" / "열리는 길 — 여기로 이어진다" / "다른 갈래"), 중앙 흐름 셰브런. 방향에 hue를 아예 안 쓰고 단일 blue 램프가 거리만 담당.

- **기대**: "한 덩어리" 문제의 구조적 해소 — 위치는 가장 강한 시각 채널. 위→아래 중력 은유가 "토대에서 올라와 다음으로 흐른다"는 서사와 일치.
- **리스크**: 탭마다 좌표 변경 → 공간 기억(지도 항상성) 파괴. 전이 애니메이션 250ms × 수십 노드 비용. 연속 탐색(후수의 후수 탭) 시 화면이 계속 출렁임. 세로 450px에 최대 7행 + 거터 밀집.
- **구현**: preset layout + `animate:true`, 밴드 좌표 계산 커스텀 코드. 난도 중상.

### C. 형태·크기 — 채움 = 방향, 크기·명도 = 거리 (좌표 불변, hue 0)

| 상태 | 채움 | 테두리 | 반지름 | 라벨 |
|------|------|--------|--------|------|
| 선택 | `#0F172A` | 흰 3px + 링 | 20px | 12px·800 |
| 선수-직접 | `#334155` 솔리드 | — | 15px | 10.5px·700 |
| 선수-뎁스2 | `#64748B` 솔리드 | — | 11px | 9px·500 |
| 선수-뎁스3 | `#94A3B8` 솔리드 | — | 9px | 9px·500 |
| 후수-직접 | `#FFFFFF` 빈 원 | `#334155` 2.5px | 15px | 10.5px·700 |
| 후수-뎁스2 | `#FFFFFF` 빈 원 | `#64748B` 2px | 11px | 9px·500 |
| 후수-뎁스3 | `#FFFFFF` 빈 원 | `#94A3B8` 1.5px | 9px | 9px·500 |
| 계보 밖 | `#EEF1F5` | — | 7px | 8px·400 저줌 생략 |

- **기대**: 은유 정합 — 채운 원 = 이미 쌓인 토대, 빈 원 = 아직 채우지 않은 것. hue 0개 → 색 예산 전부를 미래 기능(이해도 표시 등)에 남김. CVD·흑백 인쇄 완전 안전.
- **리스크**: 빈 원은 픽셀 잉크가 적어 축소·저줌에서 시각 무게 급감 — 후수 진영이 먼저 사라져 보임(질문 2의 답이 약해짐). 채움/비채움은 명도·hue보다 약한 전주의 채널.
- **구현**: 표준 속성만. 난도 하.

## ⑤ 비교 표 + 권장안

| 기준 | A 색 층위 | B 공간 재배치 | C 형태·크기 |
|------|:---:|:---:|:---:|
| Q1·Q2 (토대/열림) 즉독성 | 상 | **최상** | 중 |
| Q3 (직접/간접) | 상 | 상 | 중상 |
| "한 덩어리" 해소력 | 중상 | **최상** | 중 |
| 지도 항상성 (공간 기억) | **최상** | 최하 | **최상** |
| 모션 비용 | 0 | 높음 | 0 |
| 저줌 생존성 | 상 | 상 | 중하 |
| 난색(경고색) 충돌 | 없음 | 없음 | 없음 |
| 색 예산 소비 | hue 2 | hue 1 | hue 0 |
| Cytoscape 구현 난도 | 하 | 중상 | 하 |

**권장: A (색 층위).** 근거:

1. 기반 레이아웃이 klay 계층형이라면 위치는 이미 방향 정보를 절반 제공한다 — A는 그 위에 얹혀 "흐름으로 느껴진다" 요구를 충족하면서 B의 파괴 비용(재배치·모션)을 내지 않는다.
2. 셋 중 유일하게 세 질문 모두 "상" 이상이면서 리스크가 점진적이다. A의 리스크(원거리 톤)는 튜닝으로 해결되지만, B의 재배치와 C의 빈 원 소실은 구조적이다.
3. 정적이라 모션·성능 예산이 0 — 모바일 1차 타깃과 정합.

**보강 이식(후속)**: B의 밴드 캡션 아이디어를 A 위 오버레이 요약 칩("토대 3개 · 열리는 길 3개")으로. C의 채움/빈 원 은유는 A와 결합 가능하나 저줌 소실 리스크가 있어 2차 검토.
**탈락 조건**: 사용자 테스트에서 A로도 "한 덩어리"가 재현되면 B로 승격 — 단 Q1(재정렬 수용) 답이 선행 조건.
