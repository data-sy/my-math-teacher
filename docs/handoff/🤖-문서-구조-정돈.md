## 0. 왜 지금인가

- **이음매다.** M8 이 ①~⑤ 완주로 닫혔고 TLS 도 해소돼 차단 요소가 0이다. 마일스톤 중간에
  문서를 흔들면 진행 중 작업의 정본이 흔들리는데 지금은 그게 없다.
- **증거가 손에 있다.** 2026-08-19 하루에 백로그 4건·스크립트 4개가 생기며 서랍 문제가 실물로 드러났다.
- **독자가 바뀐다.** 포트폴리오 링크를 뿌릴 예정이라 **리포를 외부인(채용 담당자)이 본다.**
  지금까지 문서 구조의 독자는 "맥락 잃은 나 + AI" 뿐이었다.

  | 기준 | 질문 |
  |---|---|
  | 기존 | 다음 세션이 **현재 상태로 복귀**할 수 있나 |
  | 추가 | 처음 보는 사람이 **5분 안에 이 프로젝트가 뭘 했는지** 알 수 있나 |

  둘은 충돌하진 않지만 우선순위가 다르다. 예: `docs/handoff/archive/` 6개(1,000줄+ 소비 완료
  인계문)는 기존 기준으론 보존, 추가 기준으론 노이즈다. **이 관점이 결과를 가른다.**

## 1. 진단 — 무엇이 어긋나 있나

`docs/handoff/` 가 성격이 다른 넷을 담은 잡동사니 서랍이 됐다.

```
docs/handoff/
├─ 🤖-M7-인프라-티어다운-재런치.md   ← 런북(재사용). 파일 스스로 "런북"이라 적음
├─ 🤖-M8-콘텐츠-CD실증-핸드오프.md   ← 핸드오프(소비성). 제자리
├─ m7-frontend-v2-device-checklist.md ← 체크리스트(반복 사용)
├─ spec-01-verification-bundle.txt   ← 일회성 검증 산출물. ADR 3개가 이 경로를 인용
├─ scripts/ 9개                      ← 재사용 운영 도구(오늘만 5회 실행)
└─ archive/ 6개                      ← 소비 완료
```

티어다운/재런치 문서 하나에 어긋남이 셋 겹쳐 있다:

1. **위치** — 소비성 폴더에 상시 절차가 있다. 핸드오프는 쓰고 버리는 것인데 이건 인프라가
   죽을 때마다 꺼내 쓴다(2026-07-31 티어다운·08-05 재런치에 실제 사용).
2. **`🤖-` 접두사** — 전역 규칙상 🤖 = *AI 에게 먹이는 실행용*. 그런데 이 런북의 본체는
   **사람이 하는 것**이다(MFA·terraform apply·DNS). 2026-08-19 TLS 등록도 IP 동기화도 전부 사람이 실행했다.
3. **`M7-` 접두사** — 티어다운/재런치는 M7 산출물이 아니라 **프로젝트 상시 능력**이다.

`scripts/` 도 같다 — `sync-my-ip.sh`·`ssm-recover.sh`·`setup-tls-renewal.sh` 는 재발성 운영
도구지 인계 자료가 아니다.

## 2. 범위 — 손대는 것과 안 손대는 것

문서 정원 가꾸기로 번지지 않게 미리 못 박는다.

```
손댄다 (운영·조정면)
├─ 배치·이름     핸드오프(소비성) / 런북(재사용) / 체크리스트 분리
│                 🤖- 를 "AI 가 먹는 것"에만 남기기 (사람 실행 런북은 뗀다)
│                 마일스톤 접두사(M7-) 제거 — 상시 절차는 마일스톤 소유가 아니다
├─ archive/      외부 독자 기준 재평가 (→ §3 열린 결정)
└─ 진입 동선     README → ROADMAP → 현재 핸드오프 3단이 실제로 이어지는지

안 손댄다 (발견 시 멈추고 제안+승인)
├─ specs / ADR / architecture     규범 문서
├─ CLAUDE.md 계열                 거버넌스
└─ 경로 이동으로 규범 문서 링크가 깨지는 경우 → 멈추고 제안
```

**실측된 이동 비용:** 인바운드 링크 재지정 약 16곳
(재런치 런북 8 · `handoff/scripts` 6 · device-checklist 2).
ADR 3개가 `docs/handoff/` 를 인용하지만 전부 `spec-01-verification-bundle.txt` 를 가리키므로
**그 파일을 안 옮기면 ADR 은 건드릴 필요가 없다**(2026-08-19 확인).

## 4. 절차

1. **먼저 §3 을 사용자와 정리한다.** 답이 나오기 전에 파일을 옮기지 않는다.
2. 실제 상태 조사 — `ls -R docs/`, 각 문서 첫 2줄(성격), 인바운드 링크 수.
   **문서의 주장이 아니라 실물을 믿는다**(오늘 재런치 런북은 스스로 "런북"이라 적고 있었다).
3. 이동 → 인바운드 링크 일괄 재지정 → **끊긴 링크 0 확인**.
4. 커밋은 Task 단위로 분리(이동 / 링크 재지정 / archive 처리).
5. 끝나면 이 파일을 `archive/` 로 보내거나 삭제한다 — 일회성 프롬프트다.

- 죽은 링크가 HTTP 200 을 반환 → 후보 19개 중 6개가 죽어 있었다(브라우저로 잡음)
- 인증서는 유효한데 갱신 주체가 없었다 → 만료 80일 전까지 무증상
