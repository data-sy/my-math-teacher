## 1. 이번에 고친 것 (참고)

**홈 인증 상태 행 상시 노출** — `web-v2/src/screens/Home/Home.tsx`

증상: "로그인했는지 알 수가 없고 로그아웃도 못 한다."
원인: 구 규약이 *비로그인 시에만* 로그인 링크를 띄우고, 로그인 상태는 **재진입 배너**가 대신했는데
그 배너는 `queue.items.length > 0` 일 때만 뜬다 → **"로그인 + 저장된 큐 없음" 조합에서 그 자리가 통째로 빈다.**
게다가 로그아웃 진입점이 전 화면에 없어 `AuthContext.logout()` 이 **죽은 코드**였다(백엔드
`DELETE /api/v1/auth/authentication`·API 래퍼까지 전부 구현돼 있는데 호출부만 0).

수정: 인증 행을 상시 노출(비로그인 → 로그인 링크 / 로그인 → 로그아웃 버튼) + 로그아웃 시
`['queue','me']` 캐시 제거. 회귀 테스트 `web-v2/e2e/authrow.spec.ts` 3/3.

⚠️ **미처리 — 승인 대기:** 이 변경은 와이어프레임 `docs/design/v2/01-home.html:157,193` 의
*"로그인 상태면 이 링크 자체가 없음(배너와 상호 배타)"* 규약을 의도적으로 깬다.
**설계 문서는 데이터면이라 자동 수정 금지** → 사용자 승인 후 갱신할 것.

## 2. 🔴 미완 항목 4건

### A. 개념 링크(spec-03) 미구현 — **카드에 클릭할 것이 없다**

결과 화면 개념 카드의 설계(`docs/design/v2/04-result.html:281`)는
**개념명 + 시급도 배지 + 사람 언어 근거 + 무료 외부자료 링크(탭 → 새 탭)** 인데,
링크가 항상 빈 배열이다. 라이브 실측:

```json
{ "conceptName": "1부터 5까지의 수", "urgency": "HIGH",
  "blockedDescendants": 109, "links": [] }
```

원인: **`concept_links` 테이블이 프로덕션에 없다**(`information_schema` 확인 = 0).
그게 spec-03 의 산출물인데 ROADMAP 에 *"spec-03(링크) 대기 · 다음 = 프론트 재설계 후 spec-03 층"*
으로 남아 있다 — **설계만 확정(2026-07-13 U1~U6 사인오프)되고 구현이 안 됐다.**

→ 카드의 "왜 급한가"만 살아 있고 **"그래서 지금 뭘 보나"가 통째로 비어 있다.**
사용자가 "카드에 클릭 이벤트 있던 거 아니었어?" 라고 물은 지점이 여기다.

**정본:** [`docs/specs/m7/spec-03-learning-path-links.md`](../specs/m7/spec-03-learning-path-links.md)
(concept_links 테이블 · 병목 상위 30~50 시드 + 결측 허용 · 개념당 링크 3개 · goal=primary).
**규모:** DB 테이블 + 백엔드 조회 + **시드 콘텐츠 작업**(사람 손). 프론트는 이미 `links` 를 렌더한다.

### B. "이걸 모르면 위로 N개 개념이 막혀요" — 지표가 문제

`Result.tsx:190` 이 **조건 없이** 렌더한다. 전체 1,631개 개념의 실측 분포(깊이 3 역방향 폐쇄):

| blocked 수 | 개념 수 | 비율 |
|---|---:|---:|
| **0개** | **577** | **35.4%** |
| 1–4개 | 442 | 27.1% |
| 5–19개 | 417 | 25.6% |
| 20–49개 | 143 | 8.8% |
| 50–99개 | 41 | 2.5% |
| 100개+ | 11 | 0.7% |

**라이브에서 실제로 이렇게 나온다:**
```
"여러 가지 모양 알아보기" → 이걸 모르면 위로 0개 개념이 막혀요
```

문제 4가지:
1. **35%가 0개** — 급하다고 카드에 올려놓고 근거는 "아무것도 안 막음". 무의미를 넘어 역효과
2. **스케일이 널뛴다** — 같은 화면에 2개와 109개가 나란히. 비교 기준이 안 됨
3. **깊이 3 상한이 문구에 안 드러난다** — 109는 "3단계 안에서"인데 전체처럼 읽힘
4. **배지와 근거의 출처가 다르다** — 배지 = DKT 확률, 이 숫자 = 그래프 구조.
   "시급도 중인데 0개 막힘" 조합이 가능

PRD §4.3 의 의도(**절대 점수 대신 사람 언어로 상대 우선순위**)는 타당하다 — **문제는 선택한 지표**다.

**즉시 가능한 최소 개선(프론트만):** `blockedDescendants === 0` 이면 문구를 숨긴다.
**대안 검토:** 숫자 대신 후수 1개를 이름으로 지목("○○을 배우려면 먼저 필요해요")이
학생에게 더 구체적일 수 있다 — 결정 필요.

### C. 학습 경로 그래프의 라벨이 전부 숨겨져 있다

`ConceptGraph.tsx:152-156` — compact 모드에서 **모든 노드 라벨 `text-opacity: 0`, 선택 노드만 `1`.**

```js
// compact(④-B 개요) — 라벨은 선택 노드만
{ selector: 'node',     style: { 'text-opacity': 0 } },
{ selector: 'node.sel', style: { 'text-opacity': 1 } },
```

**버그가 아니라 의도된 동작이다.** 다만 사용자 보고: *"빈 동그라미만 뜨고, 클릭해야 하나씩 보인다."*
"개요"의 목적은 한눈에 구조를 파악하는 건데 아무것도 못 읽는 개요는 개요가 아니다.
전부 0으로 두는 건 과하다(짧은 이름·작은 폰트·상위 N개만 등 중간값이 있다).

### D. 🔴 선결 — 이 그래프가 무엇을 보여줘야 하는가

**C 를 고치기 전에 이게 먼저다.** 현재 ④-B 의 그래프는 **선택 개념 중심 서브그래프**
(`/api/v1/concepts/nodes/{id}` + `edges/{id}`)인데, 저장된 **학습 큐(순서 있는 체크리스트)** 와
어떻게 연결돼야 하는지가 설계에 명확하지 않다.

와이어프레임(`04-result.html:307`)은 순서만 정한다: **④-B = 그래프 → 카드 → 체크리스트**.
"학습 경로 보기"라는 CTA 이름이 약속하는 것과 실제로 보이는 것(중심 서브그래프)이 어긋난다.

→ **사용자에게 물을 것:** 이 그래프가 학습 큐의 순서를 시각화해야 하는가,
아니면 개념 간 관계 탐색용인가. 답에 따라 C 의 라벨 정책도 자동으로 정해진다.

## 3. 착수 순서 제안

```
□ D 결정 (그래프의 목적) — 사용자 답변 필요. 이게 C 를 규정한다
□ B 최소 개선: blockedDescendants === 0 이면 문구 숨김 (프론트 1줄, 즉시 배포 가능)
□ C 라벨 정책 조정 (D 확정 후)
□ 01-home.html 와이어프레임 갱신 (§1 승인 대기 항목)
□ A spec-03 착수 여부 결정 — 규모가 커서 별도 마일스톤일 수 있다
```

**B·C 는 프론트만이라 한 번의 재빌드로 묶어 배포할 수 있다.** A 는 백엔드+콘텐츠라 별건.
