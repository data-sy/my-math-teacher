## 2. ⚠️ 실행 전 반드시 아는 3가지 (가정 교정)

1. **RDS `skip_final_snapshot = true`** (`infra/terraform/database.tf:24`) → 그냥 삭제하면 **DB 데이터가 스냅샷 없이 소멸**. concepts·지식그래프·유저 데이터가 여기 있다. **수동 최종 스냅샷이 재런치의 유일한 데이터 보존 수단.**
2. **"terraform 쓰면 그대로 다시" 는 검증 안 됨.** spec-03=terraform **plan-only 샌드박스**, spec-04=실제 인프라는 **사람이 수동 프로비저닝**. → **라이브 EC2/RDS/EIP 가 terraform state 에 없을 수 있다.** `terraform destroy/apply` 가 실제 리소스와 대칭이라 가정 금지 — §3-A 에서 먼저 검증한다.
3. **호스트 상태는 terraform 밖.** env-file(시크릿)·certs·nginx `active-backend.conf`·Docker 이미지·DNS(도메인→EIP)·OAuth redirect-uri 등록은 IaC 로 복원 안 됨 → §3-C 에서 기록해 둔다.

## 3. 티어다운 전 — 검증 & 보존 (에이전트가 스크립트화, 사용자 실행)

### 3-A. 실제 인프라 인벤토리 & 프로비저닝 방식 확인 (read-only)
- `cd infra/terraform && terraform state list` → 비었거나 라이브 리소스가 없으면 = **수동 프로비저닝**(destroy/apply 무의미, 콘솔/CLI 로 직접 처리).
- AWS CLI 로 실제 리소스 대조: `aws ec2 describe-instances --filters Name=tag:Project,Values=mmt`, `aws rds describe-db-instances`, `aws ec2 describe-addresses`. 실제 ID·엔드포인트·EIP 를 기록.

### 3-B. RDS 최종 스냅샷 (데이터 보존 — 필수 선행)
- `aws rds create-db-snapshot --db-instance-identifier <실제ID> --db-snapshot-identifier mmt-mothball-2026-07-30`.
- `aws rds wait db-snapshot-available ...` → `describe-db-snapshots` 로 **Status=available·용량** 확인 후에만 삭제로 진행.

### 3-C. 재런치 상태 캡처 (기록만, 시크릿은 리포 밖 안전한 곳)
- 이미지 태그(백엔드=**재빌드 대상**, 프론트 `2.0.0`), `~/mmt-backend.env` 키 목록(값은 안전보관), `active-backend.conf` 내용, certs 도메인(lineage `www.my-math-teacher.com`), **DNS A레코드 현재 타깃(=EIP)**, OAuth 콘솔 redirect-uri 등록값, `MMT_DIAGNOSIS_ENABLED=true`.
- **(선택·권장) 스냅샷 직전 결함 ① DDL 적용:** `api/sql/create.sql:161-206` 를 프로덕션 RDS 에 적용하면 스냅샷이 M7 스키마를 품어 재런치 때 DDL 단계가 사라진다. ⚠️ `ALTER TABLE probabilities ADD COLUMN user_test_id` 는 **멱등 아님** — 적용 전 `SHOW COLUMNS FROM probabilities LIKE 'user_test_id'`·`SHOW TABLES LIKE 'learning_queues'` 로 부분적용 확인 후 필요한 문장만.

## 4. 티어다운 (완전종료 $0, 사용자 실행 — 스냅샷 available 확인 후에만)

1. RDS 삭제(스냅샷 이미 확보): `aws rds delete-db-instance --db-instance-identifier <ID> --skip-final-snapshot`(수동 스냅샷 있으니 skip OK) — **삭제 전 스냅샷 available 재확인**.
2. EC2 terminate: `aws ec2 terminate-instances --instance-ids i-0eb170169ac70ee05`. (EBS 루트=delete-on-termination 기본 → certs 등 호스트 상태 소멸, 재런치 시 재구성.)
3. EIP release: `aws ec2 release-address --allocation-id <alloc>` (release 하면 IP 반환 → 재런치는 **새 IP** → DNS 갱신 필요. IP 유지가 중요하면 EIP 만 남겨둘 수도 있으나 미연결 EIP 는 소액 과금).
4. 잔여 정리: 미사용 SG·EBS 스냅샷·CloudWatch 로그그룹 등 Project=mmt 태그로 조회 후 판단.
5. **검증은 exit code 말고 실제 state 로**(memory: destroy-verify): `describe-instances`/`describe-db-instances` 로 리소스 사라짐 확인, 멱등 재조회. terraform state 를 썼다면 `state list` 빔 확인.
