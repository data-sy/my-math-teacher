> ⚠️ **비가역 작업**(RDS 삭제·EC2 terminate·EIP release)이다. **에이전트의 SSM `send-command`·프로덕션 HTTPS·AWS 뮤테이션은 분류기 차단** → 실제 실행은 **사용자가 맥에서**. 에이전트는 확인 명령·안전 순서를 **스크립트로 만들어 전달**만 한다(맥 오케스트레이터 스크립트 패턴).

## 1. ⚠️ 실행 전 반드시 아는 3가지 (가정 교정)

1. **RDS 는 `skip_final_snapshot = true`** (`grep -n skip_final_snapshot infra/terraform/database.tf`) → 그냥 삭제하면 **DB 데이터가 스냅샷 없이 소멸**한다. concepts·지식그래프·유저 데이터가 여기 있다. **수동 스냅샷이 유일한 데이터 보존 수단.**
2. **"terraform 쓰면 그대로 다시" 는 검증된 적이 없다.** spec-03 = terraform **plan-only 샌드박스**, spec-04 = 실제 인프라는 **사람이 수동 프로비저닝**. → **라이브 리소스가 terraform state 에 없을 수 있다.** `apply/destroy` 가 실제 리소스와 대칭이라 가정하지 말고 §2 에서 먼저 확인한다.
3. **호스트 상태는 terraform 밖이다.** env-file(시크릿)·certs·nginx `active-backend.conf`·Docker 이미지·DNS(도메인→EIP)·OAuth redirect-uri 등록은 IaC 로 복원되지 않는다 → §3-4 에서 손으로 복원.

## 2. 현재 상태 확인 (read-only · 값은 여기서 얻는다)

```bash
# 프로비저닝 방식 — 비었거나 라이브 리소스가 없으면 = 수동 프로비저닝(apply/destroy 무의미)
cd infra/terraform && terraform state list

# 실제 리소스 (ID·엔드포인트·EIP 를 여기서 확보)
aws ec2 describe-instances --filters Name=tag:Project,Values=mmt --profile mmt-admin
aws rds describe-db-instances --profile mmt-admin
aws ec2 describe-addresses --profile mmt-admin

# 보존된 스냅샷 (재런치의 데이터 원천)
aws rds describe-db-snapshots --db-snapshot-identifier mmt-mothball-2026-07-31 --profile mmt-admin

# DNS 현재 타깃
dig +short www.my-math-teacher.com
```

> **AWS 세션:** 프로파일 `mmt-admin`(assume-role + MFA, ~1h). MFA 는 대화형 터미널에서만 입력 가능하므로 사용자가 맥에서 `aws sts get-caller-identity --profile mmt-admin` 로 먼저 세션을 띄운다(`!` 실행·비대화형에선 에코 불가).

## 3. 재런치 런북 (고쳐진 상태로 복구)

1. **인프라 프로비저닝** — terraform state 가 실재하면 `terraform plan` → 승인 → `apply`(spec-02 G-gate). 아니면 spec-04 수동 프로비저닝 절차.
2. **DNS** — 새 EIP 로 `www` A레코드 생성(티어다운에서 삭제했으므로). **certbot 발급이 DNS 를 요구하니 호스트 복원보다 먼저** 하고, `dig +short www.my-math-teacher.com` 이 새 EIP 와 일치할 때까지 전파를 기다린다. OAuth 는 도메인 기반이라 DNS 만 맞으면 콘솔 재등록 불요.
   - ℹ️ 전파~서비스 기동 사이에는 **A레코드는 새 IP 를 가리키는데 80/443 은 아직 안 열린** 구간이 생긴다. 이 구간을 밖에서 보면 "죽은 IP 를 가리키는 dangling DNS" 처럼 보이지만 정상 진행 상태다(2026-08-05 재런치 중 실제로 그렇게 오독된 적 있음).
3. **RDS 복원** — 스냅샷 **`mmt-mothball-2026-07-31`** 에서 restore. 이 스냅샷은 **M7 DDL 적용 이전 상태**다(다음 단계에서 적용).
4. **결함 ① DDL 적용** — `api/sql/create.sql` 의 `-- M7 spec-01:` 주석 이후 블록(자가진단 3테이블 + `probabilities.user_test_id`). 멱등 스크립트 = `api/sql/m7-apply-diagnosis-ddl-prod.sql`.
   - ⚠️ `ALTER TABLE probabilities ADD COLUMN user_test_id` 는 **멱등이 아니다.** 적용 전 `SHOW COLUMNS FROM probabilities LIKE 'user_test_id'` · `SHOW TABLES LIKE 'learning_queues'` 로 부분 적용 여부를 확인하고 필요한 문장만 실행.
5. **호스트 복원** — `~/mmt-backend.env`(시크릿 재주입) · certbot 인증서 재발급(`web/nginx.conf` 의 webroot 챌린지 순서) · `active-backend.conf` · docker 네트워크 `mmt-net`. 프론트는 compose 아닌 `docker run` 직접.
6. **백엔드 재빌드·배포** — ⚠️ 마지막으로 배포됐던 이미지 `mmt2024/mmt-backend:889390a` 는 **인증 버그 수정(track A) 미포함이라 재사용 금지.** `feat/m7-item-selection`(≥ `1c7c29e`, 이상적으로는 머지된 main)에서 **재빌드한 새 태그**로 배포. 프론트는 `mmt2024/mmt-front:2.0.0` 재사용 또는 재빌드.
7. **플래그** — `MMT_DIAGNOSIS_ENABLED=true` (호스트 `~/mmt-backend.env`).
8. **검증(마스킹 해소 확증 — 수동)** — login 200 → `GET /learning-queues/me` 가 **404 또는 200**(401·500 이면 미해결) · 존재하지 않는 경로 → **404**(마스킹 제거 확인) · 무토큰 대조군 → 401.

## 4. 티어다운 절차 (다시 완전 종료할 때 — 재사용 틀)

> 2026-07-31 에 이 절차로 mothball 실행 완료. 리소스 ID 는 그때마다 §2 에서 새로 얻는다.

1. **RDS 최종 스냅샷 (필수 선행)** — `aws rds create-db-snapshot --db-instance-identifier <ID> --db-snapshot-identifier mmt-mothball-<YYYY-MM-DD>` → `aws rds wait db-snapshot-available ...` → `describe-db-snapshots` 로 **Status=available** 확인. **available 확인 전에는 다음 단계로 가지 않는다.**
2. **(권장) 스냅샷 직전 DDL 적용** — §3-4 의 DDL 을 먼저 적용해두면 스냅샷이 M7 스키마를 품어 다음 재런치에서 DDL 단계가 사라진다.
3. **재런치 상태 캡처(기록만, 시크릿은 리포 밖)** — 이미지 태그 · `~/mmt-backend.env` 키 목록(값은 안전보관) · `active-backend.conf` 내용 · certs 도메인 lineage · DNS A레코드 타깃 · OAuth redirect-uri 등록값.
4. **RDS 삭제** — `aws rds delete-db-instance --db-instance-identifier <ID> --skip-final-snapshot` (수동 스냅샷 확보했으므로 skip OK). 삭제 직전 스냅샷 available 재확인.
5. **EC2 terminate** — `aws ec2 terminate-instances --instance-ids <ID>`. EBS 루트가 delete-on-termination 기본이라 **certs 등 호스트 상태는 소멸**한다(재런치 시 재구성).
6. **EIP release** — `aws ec2 release-address --allocation-id <alloc>`. release 하면 IP 가 반환되어 재런치는 **새 IP** → DNS 갱신 필요. IP 유지가 중요하면 EIP 만 남길 수 있으나 미연결 EIP 는 소액 과금.
7. **DNS 정리** — 재런치를 곧 하지 않을 거면 `www` A레코드를 **삭제**한다. 반환된 IP 가 타 계정에 재할당되면 내 도메인으로 남의 서버가 서빙되는 **dangling DNS** 가 된다. 삭제 후 `dig` 로 실제 사라졌는지 확인할 것.
8. **잔여 정리** — 미사용 SG·EBS 스냅샷·CloudWatch 로그그룹 등을 `Project=mmt` 태그로 조회 후 판단. IAM/OIDC/keypair 는 $0 라 보존(재런치 마찰 최소화).
9. **검증은 exit code 말고 실제 state 로** — `describe-instances`·`describe-db-instances` 로 리소스 소멸 확인, 멱등 재조회. terraform state 를 썼다면 `state list` 빔 확인.
