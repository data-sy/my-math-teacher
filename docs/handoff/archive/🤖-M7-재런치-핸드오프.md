### (이하 원문 — Phase 1 착수 전 판단용이었다)

새 세션은 Phase 0 을 마친 직후 이 3건을 **사용자에게 물어 결정**하고 진행한다. 옵션·권장·근거는 아래에 이미 정리돼 있다.

### 결정 A. RDS 를 스냅샷에서 어떻게 복원할 것인가 ⚠️ **기존 런북의 구멍**

**문제:** `infra/terraform/database.tf:12-36` 의 `aws_db_instance.app` 에는 **`snapshot_identifier` 가 없다.** 그대로 `terraform apply` 하면 **빈 `mmt-db` 가 새로 생기고**, 별도로 스냅샷을 `mmt-db` 이름으로 복원하려 하면 **식별자가 충돌**한다. 기존 재런치 런북의 "1. apply → 2. 스냅샷 restore" 는 이 상태로는 성립하지 않는다.

| | (A1) `database.tf` 에 `snapshot_identifier` 추가 **(권장)** | (A2) 콘솔/CLI 로 restore 후 `terraform import` |
|---|---|---|
| 절차 | 1줄 추가 후 apply 한 번 | restore → state import → drift 정리 |
| 장점 | IaC 가 실물과 정합, 재현 가능 | tf 코드 무변경 |
| 단점 | `snapshot_identifier` 는 이후 변경 시 replacement 유발 → 주석으로 고정 명시 필요 | state drift 수작업, memory 의 "state≠실물" 함정 재현 |

→ **권장 A1.** 코드 변경이므로 `/analyze-before-change` 대상(datasource 해석 표면). ADR 은 신규 아키텍처 결정이 아니라 **복원 절차**라 불필요 판단 — 다만 결정은 사람이.
※ A1 채택 시 주의: 스냅샷 복원은 `db_name` 을 무시하고(스냅샷의 DB 를 그대로 가져옴), `password` 는 마스터 비번 변경으로 적용된다. `username`/`engine_version`/`allocated_storage` 는 스냅샷과 호환돼야 한다.

### 결정 B. 프론트 이미지 이름 — `mymathteacher/` 인가 `mmt2024/` 인가 ⚠️ **문서 불일치**

- ADR-0011·`m7-launch-runbook.md` → `mymathteacher/mmt-front:2.0.0`
- 티어다운 런북·ROADMAP → `mmt2024/mmt-front:2.0.0`
- CI 워크플로 실제값 → `${{ secrets.DOCKERHUB_USERNAME }}/mmt-backend` = **`mmt2024`** (백엔드 기준)

→ **[사람] Docker Hub 에서 `2.0.0` 태그가 실제로 어느 repo 에 있는지 확인**(`docker pull <repo>:2.0.0` 또는 웹). 확정 후 **[AI]** 가 문서를 한쪽으로 통일한다. ⚠️ ADR-0011 수정은 **데이터면/거버넌스라 자동 수정 금지** — 제안 후 승인.

## 5. 알려진 함정 (전례 있음 — 반복 금지)

1. **미푸시 커밋으로 CI 돌리기** — `gh workflow run --ref` 는 **원격 ref** 를 빌드한다. 로컬에만 있는 수정은 조용히 무반영.
2. **exit code 로 인프라 검증** — tee 가 terraform exit 를 가린다. **AWS 실물 조회**로만 판정.
3. **MFA 1h TTL** — 긴 apply/destroy 중간에 만료된다. 끊기면 `source ./tf-assume.sh` 재실행 후 이어서.
4. **401 을 인증 실패로 읽기** — 이 앱에서 401 은 마스킹된 500/404 일 수 있었다. Phase 6 이후엔 정직해질 것이나, 판정은 반드시 위 표대로.
5. **헤더에서 토큰 추출** → CRLF 혼입 400.
6. **`COMPOSE_NET` 미설정** → 워크플로 기본값 `ec2-user_default` 로 가서 배포 실패.
7. **RDS_HOST 를 옛 엔드포인트로 두기** — 복원된 RDS 는 엔드포인트가 다를 수 있다.
   → **실제로 달라졌다**: 새 엔드포인트 = `mmt-db.c7qu444ug8bf.ap-northeast-2.rds.amazonaws.com` (§6).

### 2026-08-05 세션에서 새로 발견한 것

8. **긴 명령을 대화 코드블록으로 넘기면 붙여넣기가 깨진다** — 터미널 폭에서 접힌 지점이 실제
   개행으로 들어가 명령이 조각난다(실측: `aws rds describe-db-snapshots …` 가 4조각으로 분해,
   `export TF_VAR_db_password="$(jq …)"` 는 따옴표가 끊겨 셸이 `>` 로 멈춤).
   → **사람이 실행할 명령은 스크립트 파일로 쓰고 `bash ~/xxx.sh` 한 줄만 전달**한다.
   항목별 ✅/❌ + 마지막 판정 줄을 넣으면 사용자는 출력만 붙여넣으면 된다.
9. **~~`TF_VAR_db_password` 를 tfstate 에서 로드~~ — 이 절차는 폐기됐다(§Phase 1 교정).**
   ① destroy 가 `aws_db_instance` 를 state 에서 지우며 비번도 같이 사라졌다(현 tfstate 에 password 0건).
   ② 설령 로드해도 **terraform 변수 우선순위상 `terraform.tfvars` 가 `TF_VAR_` 환경변수를 이긴다.**
   → 실제 사용되는 값 = `terraform.tfvars` 의 `db_password`(sha256 `f8b10042…`, len 30).
   이 값은 `terraform.tfstate.backup`(destroy 직전분)의 값과 **동일** — 즉 복원해도 비번은 그대로다.
10. **저장된 plan 파일은 시크릿이다** — `var.db_password` 를 평문 임베드한다. `.gitignore` 에
    `*.tfplan` 이 없었다(추가함). plan 산출물은 리포 밖 `~/mmt-relaunch/`(chmod 700)에 둔다.
11. **⚠️ TF Serving 이미지가 3종인데 프로덕션 정본이 문서에 없다** — digest 전부 다름:
    `mymathteacher/mmt-ai:serving`(78de600b, 2024-08 · 로컬 compose 참조) ·
    `mmt2024/mmt-ai:serving`(a2099bd9) · `mmt2024/mmt-ai:serving2`(e60f2267).
    **Phase 4 에서 잘못 고르면 진단이 500 이 아니라 조용히 시급도 없이 degrade** 한다(아래 12).
    → Phase 4 전에 로컬에서 후보 이미지로 preview 를 돌려 `probabilityPercent` 분포를
    `docs/benchmark/m7-r2-dkt-selfreport.md` 의 R2 실측(0.06~0.59 → ×100)과 대조해 확정할 것.
12. **DKT fail-soft 는 조용하다** — `DiagnosisDktClient` 가 모든 예외를 삼키고 `null` 을 반환해
    `urgencyAvailable=false` 로 degrade 한다(약점 목록·학습 큐는 정상). 즉 **TF Serving 이 죽어 있어도
    Phase 6 검증 #1~#6 은 전부 통과한다.** → Phase 6 에 `urgencyAvailable` 확인을 추가했다.
13. **로케일에 따라 `sort` 순서가 다르다** — 게이트 스크립트에서 기대값을 정렬 비교할 땐
