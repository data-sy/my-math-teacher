## 2. ⚠️ 안전 원칙 (배포 전 필독)

- **원격 ref 실행:** `workflow_dispatch`·`gh workflow run` 은 **원격(push된) ref** 를 돈다. 미푸시 변경은 조용히 무반영 → **A0(push)를 반드시 먼저**, 배포 후 실제 산물로 검증.
- **다크 배포 우선:** 백엔드는 `mmt.diagnosis.enabled=false` 상태로 먼저 올려 코드만 배포(라이브 무영향) → 검증 → **플래그 ON = 기능 공개(사람 결정)**.
- **롤백 상시 준비:** 백엔드 = blue-green 이전 슬롯 or 플래그 off / 프론트 = 이미지 태그 `1.0.0` 원복.
- **사람 게이트:** Docker Hub 로그인, AWS/OIDC 트리거 승인, 플래그 ON, 실서비스 검증(OAuth 3사)은 **사람**. 에이전트는 준비·설명·검증 보조.

## 3. 실행 순서 (사용자 지정)

### A. 배포

- **A0. 브랜치 push** *(에이전트, 사람 확인)* — `git push -u origin feat/m7-item-selection`. `git status`·`git log origin/feat/m7-item-selection` 로 원격 반영 확인(위 안전 원칙).
- **A1. 백엔드 blue-green (다크)** *(사람 트리거)* — `api-ci-cd-with-ec2.yml` 를 `feat/m7-item-selection` ref 로 `workflow_dispatch`. test gate → 이미지 push → SSM `switch-backend.sh` blue-green 전환(무중단, ADR-0007). `mmt.diagnosis.enabled` 는 **false 유지**(EC2 compose env). → 다운타임 0 확인, 구 경로 무영향.
  - 에이전트: 워크플로 파일·`switch-backend.sh` 파라미터(IMAGE_REPO·NEW_TAG 등)를 `/analyze-before-change` 급으로 확인해 사람에게 트리거 절차 제시.
- **A2. 프론트 web-v2 스왑** *(사람: Docker Hub 로그인)* — ADR-0011: `mmt-front:2.0.0`(web-v2 dist+nginx) 빌드·push → EC2 `docker-compose.yml`(gitignored)의 `mmt-front` 이미지 참조를 `2.0.0` 으로 전환 → pull·재기동. 롤백 = `1.0.0` 원복. `web-ci-cd-with-ec2.yml` 경로 확인.
- **A3. 플래그 ON = 진단 공개** *(사람 결정)* — EC2 compose `MMT_DIAGNOSIS_ENABLED=true` + 백엔드 재기동(또는 blue-green 재전환). 이 시점이 실제 기능 런치.
- **A4. 배포 후 실검증** *(사람)* — 실 OAuth 3사(구글·네이버·카카오) 각 1회(소셜=가입), 게이트 경유 진단 완주 1회, 그래프 탐색, 약점0 "다음 단원" CTA, 스테일 큐 등. [기기 체크리스트](../m7-frontend-v2-device-checklist.md) 잔여 수거. 실패 시 즉시 롤백.

### B. 운영 문서 최신화 *(에이전트)*

- **`/refresh-ops-docs`** — ROADMAP·백로그·핸드오프·README 상태부를 **실제 배포 상태와 대조**해 stale 제거. M7 배포 완료·플래그 상태·프로덕션 태그(`mmt-front:2.0.0`)·미해결 백로그 반영. 거버넌스(ADR·specs·CLAUDE.md)는 자동 수정 금지(제안+승인).

### C. PR 열기 *(에이전트)*

- **`/pr`** — `feat/m7-item-selection` → `main`. 본문에 = KST 규칙 A·B·C 요약 + 단위 테스트 12건 + 라이브 검증 결과(실그래프 순서·프로브·하한17/상한20·@Autowired 버그 발견) + web-v2 UX 3건 + ADR-0012 + 배포 결과. 커밋 트레일러 없음(리포 컨벤션).

### D. 머지 *(사람 or 에이전트 — 솔로 관행)*

- PR 머지(솔로 머지 관행 = 로드맵 업데이트를 feature PR 에 포함, 별도 sync PR 없음). 머지 후 `main` 최신 확인.

### E. teardown *(에이전트, 조건부)*

- 로컬 검증 스택 정리: `docker compose stop mmt-mysql mmt-neo4j mmt-redis mmt-ai` + 로컬 백엔드(bootRun)·web-v2(dev) 프로세스 종료.
- ⚠️ **조건부 teardown** — 다른 세션이 이 인프라를 쓰고 있지 않은지 확인 후에만(무식한 자동 down 금지, CLAUDE.md 규율). 애매하면 사람 확인.
